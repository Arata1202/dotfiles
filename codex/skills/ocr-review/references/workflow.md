# OCR指摘の採否・修正・検収

目標は、基準に選んだOCR原文の各指摘に説明がつき、採用したものが実際に直った状態にすること。「OCRのところをサブエージェントでレビュー」は修正の検収を指す。全体監査や新しい改善案の募集へ広げない。

## 1. 基準を固定する

- 対象に一致する既存の結果や貼付ログがあるなら、そこから続ける。ログが途中からなら、保存済みレポートやセッションの原文を優先して探す。欠落部分を推測して全件完了としない。
- 原文は `--output` でリポジトリ外の作業用ファイルに保存し、対象SHAまたは差分、セッションID、対象・除外ファイル数、失敗や部分完了を記録する。ツールのファイル除外と、読んだ指摘の見送りは別々に数える。
- 基準は最初の有効なレポート。明示的に再実行した場合も結果を別に保存し、重複・初回のみ・再実行のみを識別する。ユーザーが基準を変更するまで初回の採否を保つ。2回目に消えたことも、新しく現れたことも、それ自体は採否の理由にならない。
- 「OCRだけ」「判断だけ」「サブエージェントで再確認だけ」の依頼ではその段階までを行う。全工程の依頼ならそのまま修正、検証、限定レビューまで進める。

## 2. 原文ごとに採否を決める

原文順に番号を付け、`番号｜箇所と指摘｜採用・見送り・重複・対応済み｜根拠｜確認方法` を控える。作業メモは一時領域で管理してよい。重複には対応先の番号を書く。報告時には原文件数と独立した問題数を混同しない。

コードと呼び出し元、サポート対象、利用者がたどる操作を照合する。採用の根拠には、誤った結果や表示、データ整合性、権限・保護、アクセシビリティ、将来の変更で食い違う具体的な依存関係などがある。発生条件と影響、修正の複雑さを比べる。重大度ラベル・多数決・個人の好みだけで決めない。明示された仕様と好みは区別する。

見送りは「低優先」だけで済ませず、前提が成立しない理由、既存の保証、あるいは得られる効果と負担を説明する。たとえば入力欄とラベル・取得処理のID一致は操作上の契約になる。同じ定数化の提案でも、固定パスの別名化は変更頻度や既存のルート管理によって価値が異なる。過去の案件の結論を次の案件に固定しない。

## 3. 採用した箇所を直す

各変更・テスト・追加依存を採用番号に結び付け、元の仕様を満たす最小の修正を選ぶ。ユーザーが確認済みのUI、挙動、個人設定は指摘との関係を確かめて扱う。「以前に戻してやり直す」は、ユーザーがその操作を依頼した場合に限る。commit・push・PRコメント・mergeも、その操作の依頼に従う。

指摘の因果関係を検証する。修正前の再現条件を修正後も使い、影響を受ける正常系・境界条件を確認する。対象に合うものを選ぶ（例：キーボードの実入力、旧形式のデータ、権限別のDB操作、再実行時に設定を壊さないこと）。静的確認・自動テスト・シミュレータ・実機を分けて記録する。

## 4. サブエージェントに修正を検収してもらう

実装後、読み取り専用のサブエージェントを使う。指摘が少なければ1名、独立した論点があれば検索・認証・DBなどの担当に分ける。親が全番号を割り当て、見送り理由も確認対象にする。各担当には基準レポート・対象番号・修正前の基準・未コミットを含む修正差分・利用可能な検証結果を渡す。

依頼文の例：

> 初回OCR原文［場所］の［番号］を担当してください。［基準］と現在の作業ツリーを比較し、元の発生条件が解消したか、修正が直接生んだ副作用があるか、見送り理由がコードと一致するかを確認してください。編集は行わず、各番号の判定、根拠、検証範囲を返してください。PR全体の改善点を新規に探す作業は対象外です。

親は指摘の妥当性をコードまたは再現で確かめる。採用した問題の未解決・修正が生んだ直接の回帰は今回中に直し、その箇所を再検証・再レビューする。独立した既存問題や任意の改善が偶然見つかった場合は、必要に応じて基準版と比較し、元のOCR指摘に該当しなければ別件として記録する。元のOCRが対象にしている既存問題は、以前からあったという理由だけでは除外しない。

## 5. 完了を判断する

採用全件に修正と検証の裏付けがあり、見送り・重複も説明でき、担当サブエージェントから直接の残件がなければ終了する。完了のためにOCRを再実行してゼロ件を目指したり、サブエージェントに対象外まで繰り返し探索させたりしない。検証不能・レビュー未実施・部分失敗があれば具体的に残す。採用ゼロなら不要なコード変更を作らず、採否の妥当性を確認する。

最終報告には基準、採用・見送り・重複・対応済みの件数と理由、確認結果、サブエージェントの判断、残件、Gitの状態を含める。「このOCR対応が完了」と「プロジェクト全体の品質保証」を区別する。「さっきは採用したか」には当時の判断と現在の差分を照合して答える。
